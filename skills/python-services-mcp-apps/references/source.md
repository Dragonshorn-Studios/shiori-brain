# Python Services & MCP Apps

Shared guidance derived from Belldandy and related Dragonshorn Python services.

## Environment
- Read `pyproject.toml`, the lockfile, `AGENTS.md` and CI before choosing APIs.
- Use the repository's declared Python version and package manager; current projects commonly use Python 3.12+ and uv.
- Keep dependencies minimal and pinned through the established lock workflow.
- Use type hints for public boundaries and data models.

## Service design
- Validate all external input at the edge.
- Keep transport adapters such as FastAPI or MCP thin; put policy and domain behavior in testable modules.
- Prefer proposal-oriented tools for consequential operations.
- Require an explicit human approval step before external mutation when the product contract calls for it.
- Enforce allowlists at the execution boundary and fail closed.
- Encrypt stored tokens and never log, return or embed credentials.

## Web UI
- Follow the project's existing rendering approach, including Jinja/HTMX where used.
- Keep server-rendered interactions small and accessible.
- Reuse components and avoid introducing a frontend framework for a localized interaction.

## Verification

Typical checks, when present in the repository:
- `uv sync`
- `uv run pytest`
- `uv run ruff check`
- `uv run python -m <package>`

Add tests for authorization, validation, approval gates, adapter failures and redaction. Use fakes for remote systems and temporary directories for filesystem work.
